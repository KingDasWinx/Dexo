## What Dexo's grid has today (checked in code, not only in docs)

Checked in `crates/dexo-tui/src/keymap.rs` (`[results]` in all three profiles), `palette/registry.rs`, `widgets/grid.rs` and `model.rs`:
- Server-side WHERE and ORDER BY bars (`w`, `o`). Sort by column `s` and add a column to the sort `S`, both run on the server. Paging `n`/`p`. Exact count `t`, which runs on its own connection and can be cancelled. Related rows `f`/`b`. Record view. Value inspector/JSON viewer. Row/column select `r`/`c`. Shift+Up/Down range. Ctrl+Enter picks rows. Copy as CSV/JSON/Markdown/SQL/text. Inline edit/insert/delete with review. Zebra rows. Header sort markers. Mouse header sort.
- Rendering only touches the rows on screen (`visible_slice`). There is a 100k-row viewport smoke test. Column widths come from the visible window, capped at 40 (`model.rs:1188-1235`).
- **Plumbing that has no UI.** `GridModel.frozen_columns`, `hidden_columns`, `freeze_columns()` and `hide_column()` exist (`model.rs:335-336, 1062-1070`). `visible_column_indices()`, `ensure_column_visible()` and `selected_matrix()` (copy) already honour them. Only a test calls them (`grid.rs:752-776`). No key, palette entry or doc exposes them.
- **Generic SQL wrapper.** `dexo_sql::derived::filtered(select, sql, filter, clauses, dialect)` (`crates/dexo-sql/src/derived.rs:71`) builds `SELECT <anything> FROM (<user query>) AS _dexo_derived WHERE …` and refuses non-read and locking statements. `t` uses it through `derive_count_in`. Column stats and frequency tables can use the same wrapper. Typed filters with bound values exist too (`model.data.filter`, used by related rows, `update.rs:7706`).

## 3. Things they do better than Dexo's grid where Dexo has the feature

1. **Wide rows: Dexo squeezes every column to fit instead of scrolling.** `allocate_column_widths` (`model.rs:1345`) keeps every column from `column_offset` to the end as long as each can get one character, and shrinks the widest columns until they all fit. I compiled a copy of the function: 30 columns of natural width 14 in a 120-cell pane all come out **3 characters wide** (`ab…`), and 12 columns of 12 in a 100-cell pane come out 7–8. The other three tools keep natural widths and scroll:
   - visidata lays out columns left to right at natural width, capped at `default_width = 20`, minimum 4, until the screen ends, then shows `>` for more (`visidata/sheets.py:720-760`, `interface.py:7,55`).
   - pspg scrolls by column (Shift+arrows) or by character (Ctrl+arrows) and keeps frozen columns.
   - tabiew had Dexo's exact behaviour and users reported it: [#35](https://github.com/shshemi/tabiew/issues/35) "The more columns there are, the more data … is truncated", 2 👍. The fix was to switch automatically to an "Expanded" mode (natural widths plus horizontal scroll) when the compact layout cannot fit (`src/tui/table.rs:194-205, 400-404`; panes now start in Expanded mode, `with_extended_column()`, `src/tui/pane.rs:66`). [#102](https://github.com/shshemi/tabiew/issues/102) "Wide tables are not displayed properly" (200 columns) is still open.

   Dexo's `ensure_column_visible` already scrolls by natural widths, so the fix is mostly in `allocate_column_widths`. Keep natural widths for the columns that fit, cut only the last partial column, keep the `…` overflow marker, and make sure the cursor column is always whole.
2. **NULL is indistinguishable from the string `'NULL'`.** `format_value` renders `DbValue::Null` as the text `NULL` (`model.rs:1238`) in the row's normal style (`grid.rs:576-583`). visidata draws `⌀` in a dedicated note colour (`interface.py:3`, `column.py:386`). pspg shows `∅` or a user string (`--null=STRING`), with an "Empty string is NULL" toggle. Fix: a dim glyph or styled `NULL`, plus a theme role.
3. **Numbers are left-aligned.** Every cell is `format!("{:width$}")`, which left-aligns (`grid.rs:577`). tabiew right-aligns numeric cells and numeric headers (`src/tui/table.rs:626-636, 676-679`). psql output, which pspg displays, does the same. Right-aligned digits make magnitudes comparable at a glance.
4. **No current-cell or current-column highlight.** Dexo highlights the whole active row and marks the column only in the header. visidata colours the current column and the current cell (`color_current_col`, `color_current_cell`, `sheets.py:167,171`). pspg has a vertical cursor (`Alt+v`, or double-click a header) and a "cross cursor" cell. In a 40-column grid you lose track of which cell `s`, Enter or copy will act on.
5. **No column separators.** visidata draws `│` between columns and a distinct separator after key columns (`disp_column_sep`, `disp_keycol_sep`). pspg draws full borders (3 styles). Dexo uses one space, which makes squeezed or empty columns hard to tell apart.
6. **Theme roles for tables.** pspg custom themes have table-specific keys: `cursor_data`, `cross_cursor`, `matched_pattern`, `row_number`, `bookmark`, `label` for frozen and header cells (`README.md` "Custom themes"). Dexo's roles (`docs/src/workbench.md:28`) are generic: selection, zebra, focus. Add `null`, `number`, `current-cell` and `search-match` when the features above land.
7. **Copy is two steps away.** pspg's `Ins`, visidata's `y` and tabiew's `c` copy with one key. Dexo needs Enter, then a menu pick (`palette.rs:167` `results_menu_items`). Dexo also has more formats than tabiew and fewer than pspg, which has SQL VALUES, pipe-separated and TSV for LibreOffice.
8. **Discoverability.** pspg has an F9 menu bar listing every action with its key (`src/menu.c`). tabiew's README has a key table. Dexo's docs (`docs/src/workbench.md` "## Results") describe neither the record view, picking rows, copy formats nor the Enter menu. The help overlay may list them, but the docs do not.
9. **Search runs in the background.** tabiew searches on worker threads and streams partial matches into the view, so typing never blocks (`src/misc/search.rs`, `spawn_search_thread` / `spawn_collector_thread`). When Dexo adds search, 100k loaded rows × 40 columns of `format_value` is too slow per keystroke on the UI thread. Debounce the input, or match on a worker thread.

## 5. Not worth copying, and why

- **Pivot, melt, join of sheets, computed Python columns, regex split/capture columns** (visidata `W`, `M`, `&`, `=`, `:`/`;`) and **SQL over the loaded result** (tabiew's polars-sql). Dexo sits on a real database, and on DuckDB for files, so the user writes the JOIN, GROUP BY or CASE in SQL and gets an exact answer over all the rows. A second in-memory query engine would duplicate the editor, the autocomplete and the safety checks for a worse result.
- **Scatter and line plots** (tabiew `scatter_plot.rs`, visidata `graph.py`). These are large, rarely used in a DB workbench, and hard to make readable in a terminal. Inline bars in the frequency popup cover the "what is the distribution" question.
- **400 themes** (tabiew `src/tui/themes/`, 400+ files) and pspg's retro themes. Dexo's presets plus a custom role file are enough. Add table roles instead (section 3 item 6).
- **visidata's sheet-stack model and cmdlog macro replay.** These are powerful but the reason for visidata's learning curve. Dexo's documents, saved queries and WHERE/ORDER BY bars already give reproducible views.
- **Row sliding, random sample, dedupe, incremental-number columns, conditional-format expressions, sparkline columns** (visidata `slide.py`, `random_sample.py`, `dedupe.py`, `incr.py`, `condfmt.py`, `sparkline.py`). For result sets these are SQL one-liners (`ORDER BY random() LIMIT n`, `DISTINCT`, `row_number()`) or niche.
- **pspg's pager plumbing** (`--stream`, `--querystream`, `--quit-if-one-screen`, primary-screen toggle). These exist because pspg sits behind psql, and Dexo owns the whole session.
- **Client-side sort** (pspg `a`/`d`/`u`, visidata `[`/`]`). Dexo's server-side sort is exact across pages. Keep it.

## 6. Top 5 recommendations for Dexo's results grid, ranked by value/effort

1. **Fix wide results, then wire freeze and hide (S–M, highest value).** Stop squeezing in `allocate_column_widths`: natural widths (cap 40), horizontal scroll, `…` on the last partial column, cursor column always whole. tabiew hit the same complaint (#35, #102) and fixed it this way. Then expose the existing `freeze_columns` / `hide_column`: digits `0`–`9` freeze N columns (pspg), auto-freeze the primary key on table documents, `-` hides a column, one unhide-all command, and "hide all-NULL columns". Mark frozen columns with a separator. Files: `model.rs`, `widgets/grid.rs`, `keymap.rs` (3 profiles), `palette/registry.rs`, `docs/src/workbench.md`.
2. **Make cells readable at a glance (S).** Draw NULL as a dim `∅`/`NULL` with its own role, right-align numeric cells and headers, highlight the current cell (or column), show "row r / n · col c / m" in the grid title, and bind `y`/`Ctrl+C` to copy the selection. All of this is local to `grid.rs` `preview_lines`/`rows_label` plus the theme roles.
3. **Selection stats and filter-to-value (S).** When a range or column is selected, the title shows count · non-null · distinct, and sum/avg/min/max for numeric columns, over the selected loaded cells (visidata `z+`, without the key). Add `=` / "Filter to this value" (and `IS NULL`) through the existing typed filter, so it is server-side, bound and exact.
4. **Search inside results (M).** `/` opens an incremental search over the loaded rows and all visible columns. It highlights matches, jumps to the next and previous match (F3/Shift+F3, since `n`/`p` page the grid), says its scope ("in 10,000 loaded rows"), and debounces or uses a worker thread. Add a go-to-column fuzzy picker, which matters most on wide tables. pspg, visidata and tabiew all have search. In Dexo today, finding anything means writing a WHERE.
5. **Column profile popup (M).** `F` on a column runs on the server, through `dexo_sql::derived::filtered` like `t`, on its own cancellable connection. It shows the top 50 values with count, % and an inline ■ bar, plus a summary line: rows, nulls, distinct, min, max, and avg/sum for numerics; numeric columns get quantile buckets. Enter on a value filters the grid to it. This covers visidata's `F` and `I` and tabiew's histogram in one place, gives exact answers over the whole result rather than only the loaded rows, and is the most-requested chart in these trackers. tabiew's MIT ratatui `BarChart` code shows how to draw it if bars inside a table are not enough.

Next after these: watch mode (S–M, pspg `-w`), per-column width toggle (S, visidata `_`), row-number gutter (S).
