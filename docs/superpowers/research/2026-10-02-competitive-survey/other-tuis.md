# Other TUIs vs Dexo: lazysql, sqlit, harlequin, dblab, vi-mongo

Researched 2026-10-02 from shallow clones in `/home/winx/Documents/dexo-examples-projects/tui/`, plus `gh` (issues, releases, discussions). Dexo was checked at `development` (1.4.2). Before calling something missing, I grepped `docs/src/` and `crates/`, and I traced code paths for the claims that matter. Paths are relative to each repo's root.

## 3. Things they do better even where Dexo has the feature

1. **Team config and onboarding.** Each of the four SQL tools reads a plain file from the project folder (lazysql, harlequin, dblab) or keeps a project folder (sqlit `.sqlit/`). harlequin also gives env interpolation with defaults, secret masking, a JSON Schema for editor completion, `--config validate` with file and key in every error, and `--config show` with the source of each value. Dexo's export/import TOML is portable but opaque (UUIDs, JSON inside strings) and is not discovered.
2. **History.** harlequin records the outcome and which program ran each query, filters by both, and shares one history between TUI and CLI. sqlit keeps history per connection, with starring and cross-connection fuzzy search. Dexo keeps 500 SQL strings for all connections, from the TUI only (item 9).
3. **CLI contract.** hsql treats exit codes and stdout/stderr as an API, announces truncation, and exposes `--spec`/`--info`. Its ad-hoc use (`hsql file.db -c …`) needs no saved profile. Dexo's guardrails on the CLI are stronger (policy, `--confirm-target`), but its ergonomics are weaker (item 8).
4. **Grid ergonomics.** lazysql has Vim-style row marking: `Space` marks a row, `v` starts a live range, and `Y` copies as SQL/Markdown/JSON/CSV with an INSERT for table rows (`components/row_copy.go`). It counts exactly on demand with `#` and cancels with `#` again, which Dexo matches with `t`. Its reverse foreign-key picker uses `f`, which Dexo also has. Dexo has row picks and selection, but no cell edit, column hiding or in-grid find (items 1, 11, 12).
5. **DuckDB.** harlequin opens `harlequin` (in-memory DuckDB) or `harlequin file.parquet` straight away. In Dexo the same requires building from source (item 4).
6. **Defaults that survive real terminals.**
   - harlequin binds **both** `ctrl+enter` and `ctrl+j` to run a query (`src/harlequin_vscode/__init__.py:26`, "^⏎ or ^j"). Its discussion #598, "Ctrl + Enter does not execute the query on many terminals", has 9 comments. Dexo's only run-statement key is `ctrl+enter`, and `ctrl+shift+f10` runs the document (`crates/dexo-tui/src/keymap.rs:615`). Commit `958081b` removed F5/F8 on purpose to match DataGrip. Dexo turns the kitty keyboard protocol on when the terminal supports it (`keys_disambiguated`, `event.rs:113`). On terminals without it (VTE/GNOME Terminal, Terminal.app, tmux without extended-keys) Ctrl+Enter arrives as Enter, so the only way left to run a statement is the palette. This needs checking; a fallback chord is an S fix.
   - lazysql's `default` theme uses the terminal's own background, and its theme picker (Ctrl+T) previews live and puts the old theme back on Esc. sqlit follows the Omarchy theme (`sqlit/domains/shell/app/omarchy.py`). lazysql #181, "Color scheme does not adjust for light terminal colors", had 11 👍. Dexo's low-color mode is close; a "terminal colors" preset that maps roles to the ANSI 16 colors would cover it.
7. **Packaging and docs.**
   - lazysql and harlequin are in **homebrew-core** (`brew install lazysql`) rather than a tap. sqlit has a Nix flake plus `uvx sqlit-tui`. vi-mongo has a `curl | sh` installer and a Neovim plugin. harlequin, dblab and vi-mongo each run a **docs website** (harlequin.sh, dblab.app, vi-mongo.com).
   - Dexo is not on crates.io (`cargo install dexo` returns 404). A community AUR `dexo-bin` exists, but `install.md` never mentions it.
   - Dexo's mdBook (`docs/book.toml`) is not published: no Pages workflow in `.github/workflows/`. It also declares `language = "pt-BR"` while the docs are in English.
8. **Debuggability.** harlequin has F12 "Debug information" and writes a crash report with exit 70. vi-mongo has `--paths`. Dexo's `doctor --json` and Export Diagnostics are on par; nothing to copy.

Where Dexo is clearly ahead, so there is nothing to copy: guardrails (server-enforced read-only, production typed-name, destructive confirms in TUI, CLI and MCP), EXPLAIN tree and plan comparison with hypopg, schema diff and DDL forms, MCP grants with Agent Activity, LSP, crash recovery, SSH known-hosts checks, the keychain, and Docker discovery.

## 5. Not worth copying

- **An AI chat or natural-language-to-query box inside the TUI** (vi-mongo `internal/ai/`, which needs `OPENAI_API_KEY` or `ANTHROPIC_API_KEY`). harlequin turned it down (#952, closed as not planned; `docs/plans/harlequin-for-agents.md` §3.9 says "No LLM inside Harlequin"). Dexo's MCP with grants is the stronger position, and API keys go against local-first.
- **Driver auto-installer and pip adapter plug-ins** (sqlit's dependency wizard, harlequin's adapters). These solve Python packaging. Dexo ships one binary.
- **sqlit's provider long tail** (osquery, SurrealDB, Teradata, Spanner, Flight SQL and so on). Each driver would have to meet Dexo's bar: catalog, EXPLAIN, editing, server-side read-only and policy parsing. Do MSSQL first and maybe ClickHouse.
- **MongoDB and an aggregation builder** (vi-mongo). It is a different data model, the guardrails and parser would need redoing, and it is L+ for 2 👍.
- **Running several statements concurrently in separate tabs** (dblab, up to 5). It breaks statement order and transactions; Dexo runs them in order with result tabs, which is right.
- **A leader-key (Space) menu** (sqlit). The palette, footer hints and F1 already cover discovery, and Space would clash with Vim mode.
- **Theme sync tied to Omarchy** (sqlit). It is niche; a generic "terminal colors" preset covers it.
- **Chained pre-connect commands with `SaveOutputTo`** (lazysql). The shell can do it. Dexo's single `pre_connect` with process-group cleanup is safer.
- **hsql `--serve` warm sessions.** Dexo's MCP server already keeps connections warm, and a Rust CLI starts fast. Revisit only if agents adopt the CLI heavily.

## 6. Top 5 recommendations, ranked by value/effort

1. **Catalog search and Go to Object (S, then M; High).** Wire `/` in the explorer to the existing `ExplorerState.search` with `n`/`N`. Then add a palette-style fuzzy picker ("Go to Object…") over the cached catalog, which also lists objects not loaded yet. It is the biggest daily-use gap and costs the least, because the filtering and rendering code is already in `screens/explorer.rs` and `widgets/object_tree.rs`.
2. **Cell editing in the grid (M; High).** Add inline edit (Enter or `F2`), a NULL/DEFAULT toggle, `$EDITOR` for long values or JSON, and Duplicate Row. Stage edits through `ChangeSet::update` and send them through the existing review, production and read-only gates. Until then, the README claim "edit rows in the grid" overstates what the TUI does. This answers harlequin discussion #653 (9 upvotes), and lazysql and sqlit both have it.
3. **Launch and CLI ergonomics bundle (S; Med-High).**
   - Launch: `dexo ./shop.db`, `dexo data.parquet` (inferred scheme), `dexo <saved-name>`, `dexo --read-only <url>`.
   - CLI: `dexo query --url …`, `--limit` and `--timeout` per call, distinct documented exit codes (hsql's table is a good model), `--format markdown|vertical`.
   - Keys: a run-statement fallback chord for terminals without the kitty keyboard protocol (harlequin binds `ctrl+j` next to `ctrl+enter`). Check first whether Dexo already handles this.
4. **Repo-local `.dexo.toml` (M; High for teams).** Found from the cwd up to the git root; hand-written connections, groups, environment and policy; no secrets (`${env:VAR}`, `password_command`); a trust prompt before running any `pre_connect` from the file; a published JSON Schema; `dexo config validate`. This answers lazysql #202 and #155 and vi-mongo #126, and matches harlequin and lazysql.
5. **DuckDB in release artifacts (M; High for the data segment).** Ship a `dexo-duckdb` archive per target, or link `libduckdb` dynamically, so `dexo sales.parquet` works after `brew install`. It is lazysql's top request (13 👍) and harlequin's default.

Close behind:
- Quick find in the grid plus column hide/freeze (S each; the hide/freeze code already exists).
- Browsing other databases on the same Postgres server (M).
- One shared, searchable history with outcomes and a `dexo history` command (S–M).
- MCP for SQLite and DuckDB (M).
- A docs site from the existing mdBook, and fixing `language = "pt-BR"` (S).
- The big bet is the **SQL Server driver (L)**: it is the most common driver the competitors have and Dexo does not.
