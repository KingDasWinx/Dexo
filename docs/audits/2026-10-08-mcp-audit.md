# MCP audit, 2026-10-08

Six read-only audits of the MCP path after the write-access redesign (commits 6ef806b9,
9ecb0ecc, 52406bf9), plus a tester's report against a live Postgres 16 (profile
`assistant`, connection `tdediego`). Every finding below has a file and a fix; a plan
turns them into tasks. "Confirmed" means reproduced with a test, a probe or on the
tester's machine; the rest were found by reading.

## Critical

| # | Finding | Where | Fix |
| --- | --- | --- | --- |
| C1 | **Function denylist bypassed by Unicode-escaped identifiers.** `SELECT U&"pg\005fread\005ffile"('/etc/hostname')` passes the guard and runs: sqlparser does not decode `U&"…"`, it parses `U & f(args)` as a bitwise op, so the function name is compared raw; Postgres decodes it. Every denied function (`pg_read_file`, `pg_ls_dir`, `lo_import`, `dblink`, `query_to_xml`, `pg_sleep`…) is reachable; the read-only transaction does not cover these. Confirmed (test + tester). | `crates/dexo-sql/src/statement_guard.rs` `parse_one`, `deny_function` (~723), `path()` (~617) | In `parse_one`, for Postgres and DuckDB, refuse any statement holding `u&"` or `u&'` (case-insensitive, outside ordinary quoting) as `GuardRejection::Unparsed`; `ponytail:` comment naming the ceiling. Unit tests for the escaped function, the escaped relation and the plain `U&"pg_sleep"` control. |
| C2 | **An older Dexo archives the live database and restores a backup under running processes.** `recover_unsupported_schema` treats a newer schema as unsupported, renames `dexo.db` to `dexo.db.unsupported-vN` and copies `.bak` back; `mcp_backend.rs` reopens the DB per tool call, so a 1.4.2 server started by Claude Code did this twice while the dev TUI kept writing into the archived inode. Nothing is logged. Six archives (~15 MB) on the tester's machine; grants made in the TUI never reached the server. Confirmed on the machine. | `crates/dexo-storage/src/database.rs:53-64, 122-131, 167-188`; `crates/dexo-cli/src/mcp_backend.rs:24,80,91,103,110` | Replace archive+restore with a hard error: `dexo.db was written by a newer Dexo (schema N); this build reads M: upgrade Dexo`. Keep `backup_before_destructive_migration`. Propagate the WAL rename error in `move_database_bundle`. Open the DB once in `mcp_backend`. On `open`, say once where old `dexo.db.unsupported-v*` files are (no deletion of data). |

## Checked and sound

Multi-statement, locking clauses, `EXPLAIN ANALYZE`, `SELECT INTO`, data-modifying CTEs, the plain function denylist (schema-qualified, FROM-clause, window, FILTER, constructors, quoted and mixed case), relation allowlist (joins, subqueries, CTE names, escaped relation names fail closed), write target extraction (`INSERT … SELECT`, `CREATE TABLE AS`, `MERGE` and `WITH … DELETE` refused), destructive classification and `confirm_target`; `tools/list` and `tools/call` gate on the same list; `ttlMs`/`cacheScope`; `connection` required only with several; `data_read` paging and limits; cancel rolls back; replace-on-insert and revoke deny waiting writes in one transaction; approval deadline clamp and settle guards; `parse_ttl`; migration 19 on `remaining_uses`; `serve` fails closed for disabled, missing and connection-less profiles; `setup` paths, merges, backups and skill files for all seven clients; `doctor --probe`; `audit` keeps SQL as a hash.
